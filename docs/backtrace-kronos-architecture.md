# DSA × Kronos 集成架构对账（DSA-KRONOS-V1.0 #35）

> 来源：用户「Kronos 完整解析 + 系统集成全方案」蓝图。
> 定位：Kronos（清华大学开源、AAAI2026 收录的全球首个金融 K 线专用时序基础大模型，
> GitHub `shiyu-coder/Kronos`，HuggingFace 权重 `NeoQuasar`）作为 DSA 反向归因系统的
> **【技术面统一算力底座】** 接入，与现有「事件 / 舆情 / 基本面」逻辑中枢并行，形成
> 「事件舆情 + 量价技术」双驱动一体化量化系统。

## 一、与现有 DSA 反向归因架构的关系（核心设计决策）

现有外挂信号源（`#23 行情 / #25 披露 / #28 头条舆情 / #31 微信舆情 / #34 短线快讯`）
**本质都是「事件 / 情绪催化源」**：在 `scan_alerts(watchlist=None)` 时把各自事件池标的
**叠加（union）进闭环扫描候选池**，与大涨池正交互补。

Kronos 与上述四类**本质不同**：它是**逐只股票的技术面算力底座**，不对扫描候选池做
union 扩张，而是对已经扫描出的每只 alert **富化技术面信号（`kronosInfo`）**：

- 趋势（多头 / 空头 / 震荡）、趋势强度、拐点（无顶部拐点 / 顶部拐点·高位见顶 / 底部拐点·下跌末端反转）
- 上涨 / 横盘 / 下跌三态概率分布（Kronos 概率多路径预测，适配风控场景）
- 波动率、量能评分、持续性文本、由 BSQ Tokenizer 隐向量派生的候选 Alpha 因子

并**独立输出三类选股池**（短线强势池 / 趋势反转池 / 风险预警池）供业务层消费（蓝图 §四 能力1）。

> 因此 #35 不走 union 叠加路径，而是走「逐 alert 富化 + 独立选股池视图」，内核 `run_closed_loop`
> / `propagate_shock` 零改动。

## 三、五层集成架构对账

```
【数据接入层】→【特征融合层】→【双模型推理层】→【标准化输出层】→【业务落地层】
```

1. **数据接入层**：复用 AkShare 行情（OHLCVA）→ Kronos；全平台舆情/公告 → llm_parse_service。
2. **特征融合层**：文本侧（情绪分/事件/可信度/圈层阶段）与 K 线侧（趋势/拐点/概率/波动率/量能/因子）统一 JSON 对齐、归一化。**本模块即 K 线侧特征产出方**。
3. **双引擎推理层**：`Kronos Service`（时序量价，技术面信号）与 `DSA 主引擎`（事件+基本面+舆情+量价，最终涨跌/置信/长短权重）。
4. **标准化输出层**：在原有 alert JSON 上新增 `kronosInfo` 字段（见 §四），兼容旧系统。
5. **业务落地层**：收盘批量复盘选股、大涨反向深度归因、盘中风险预警、周末因子回测。

## 四、标准化输出字段（kronosInfo，嵌入 alert）

```json
{
  "stockCode": "600519",
  "stockName": "贵州茅台",
  "trend": "多头趋势",
  "momentum": 0.71,
  "inflectionPoint": "无顶部拐点",
  "riseProb": 0.72,
  "sidewayProb": 0.21,
  "downProb": 0.07,
  "volatility": 0.18,
  "volumeScore": 0.64,
  "persistence": "中期上升趋势，量价配合，可持续 1~2 周",
  "factorScores": [
    {"name": "BSQ趋势强度因子", "score": 0.71},
    {"name": "分层量能因子", "score": 0.64},
    {"name": "波动率压缩因子", "score": 0.82},
    {"name": "拐点共振因子", "score": 0.80}
```

`BacktraceKronosSignal` 伴随表（`Base.metadata.create_all` 自动建表）持久化上述字段，
`factorScores` 以 JSON 文本存储，供选股池、因子库（P2）复用。

## 五、权重与风控硬约束（蓝图 §七，已固化）

| 约束 | 取值 |
|---|---|
| K 线信号短线权重上限 | **0.35**（`KRONOS_WEIGHT_SHORT_CAP`） |
| K 线信号长线权重上限 | **0.15**（`KRONOS_WEIGHT_LONG_CAP`） |
| 决策权 | Kronos 仅输出技术参考；最终涨跌量化 / 中长期结论由 DSA 数学模型决定 |
| 防过拟合 | 新增 Alpha 因子必须经历史回测验证方可入库（本模块只产出候选因子，不自动入库） |
| 黑天鹅优先 | 极端政策 / 突发黑天鹅优先采信事件舆情，弱化 K 线预判 |

> 这些权重是**硬上限**而非实际并入合并模型的权重；本模块**不修改** DSA 现有长短线权重合并模型
> （见 `docs/backtrace-opinion-architecture.md` §五.2），仅在前端 `KronosSourceInfo` 中展示上限约束。

## 六、分阶段排期对账

- **P0（本次 #35）**：本地部署 Kronos-small 轻量化模型接口（mock 确定性底座）→ 单股 / 批量技术面分析 → 三类选股池 → 逐 alert 富化 `kronosInfo` → 前端技术面面板 + 预警列。交付：单股 K 线分析、基础概率预测、简单选股功能。
- **P1（待建）**：千股并行批量预测工程化、舆情×量价联动融合规则、反向归因量价结构溯源、拐点预警、Qlib 回测适配。
- **P2（待建）**：自动因子挖掘与模型迭代闭环、分钟级实时盘中监控、各信号历史胜率固化最优权重、Web 可视化整合。

## 七、真实环境适配（优雅回退）

- 环境变量 `DSA_REALTIME_KRONOS=1` 触发真实模型路径；未开启 → 确定性 mock。
- 真实环境若 torch / transformers / NeoQuasar 权重缺失 → 抛 `ProviderUnavailable` → 回退 mock 并记录原因，保证回溯闭环在任意环境可运转。
- 沙箱无网络 / 无权重 / 无 GPU → 全程走 mock，接口契约不变，全链路可端到端验证。
